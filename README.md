# Teleprompter

A local teleprompter project for displaying song lyrics and chords on a monitor. The intended setup is a Raspberry Pi connected to a screen and a USB macro keypad.

> **Status:** Work in progress. The setup below is based on the configuration discussed so far; song management and performance controls still need to be implemented.

## Planned features

- Display lyrics with chords above the relevant words.
- Import, list and edit songs in a repertoire.
- Create ordered setlists that reference songs in the repertoire.
- Control the display using a USB macro keypad.
- Run locally without internet access once the required software, images and assets are available.

## Architecture

- **Frontend:** Vite application, built into static files and served by Nginx.
- **Backend:** Fastify application running in a Node.js container.
- **Storage:** A host folder bind-mounted into the backend container for song files. 
The frontend will communicate with the backend to manage songs and setlists. The exact API and setlist storage are still to be implemented.

## Prerequisites

- Docker and Docker Compose.
- Node.js and npm to build the frontend on the host.
- A project with the frontend, backend, Compose file and Nginx configuration in the locations shown below.

An internet connection is needed to download dependencies and container images initially. After they are available locally, the running app is intended to work offline.

## Expected project structure

```text
teleprompter/
├── compose.yaml               # or docker-compose.yml
├── frontend/
│   ├── nginx/nginx.conf
│   ├── package.json
│   └── dist/                  # generated by the Vite build
└── backend/
    ├── Dockerfile
    ├── package.json
    └── repertoire/            # bind-mounted song folder
```

Adjust the paths if your project differs. Vite normally outputs to `dist`; check your Vite configuration if you use another folder.

## Run locally

1. From the project root, build the frontend:

   ```bash
   cd frontend
   npm install
   npm run build
   cd ..
   ```

2. Ensure `frontend/nginx.conf` exists as a file and `backend/repertoire` exists as a folder. The backend's `package.json` must define a working `start` script.

3. Start the services from the directory containing your Compose file:

   ```bash
   docker compose up --build
   ```

4. Open **http://localhost** for the frontend. If port `3001:3001` is mapped in Compose, open **http://localhost:3001** to test the backend. The initial Fastify route returns `{"hello":"world"}`.

To stop the services, press `Ctrl+C`, then run:

```bash
docker compose down
```

The frontend is served from the built files. Run `npm run build` again after changing frontend code to update `dist`. Rebuild the backend image after changing its code.

## Repertoire storage

With the Compose mount `./backend/repertoire:/app/repertoire`, the host folder is available to the backend at `/app/repertoire`. Files written there persist when the container is recreated. Back up the host folder separately.

The mount itself does not implement importing or editing songs: Fastify routes and file-handling code are needed for that.

## Troubleshooting

- **Nginx mount error:** Confirm `./frontend/nginx/nginx.conf` is a file and that the path in Compose matches its actual location. If Docker created a directory at the file path, check its contents before removing it.
- **Frontend is missing or outdated:** Build the Vite app and confirm Compose mounts the correct output directory.
- **Backend cannot be reached:** Check that Fastify listens on `0.0.0.0:3001`, its container is running, and port 3001 is published if accessing it directly.
- **Port already in use:** Stop the other service or change the host port in Compose.
